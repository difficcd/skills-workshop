# telegram-notify

**컴퓨터만 켜 두면, 폰의 텔레그램으로 그 머신의 에이전트 세션들을 관리하고 지시한다.** 자리를
비운 동안 에이전트가 텔레그램으로 보고하고, 사용자는 답장으로 지시하고, 세션이 여럿이면 번호로
골라 보내고, 놀고 있는 세션은 자기 앞으로 온 메시지가 도착하는 순간 깨어난다. 연동 절차, 보낼
때와 안 보낼 때의 기준, 그리고 자유 서술로는 답할 수 없는 한 가지 질문 — *이 세션이 아직 살아
있나?* — 에 답하는 고정 보고 형식까지 들어 있다.

Node 18+, 의존성 0. Claude Code 용으로 만들었지만 구성 요소는 평범한 스크립트다 —
[이식](#이식) 참고. English: [README.md](README.md).

```
폰                                      컴퓨터 (켜 두기만)
 ?                    ───────────▶       1 my-app · 2 other-app (closed)
 1 테스트 돌려        ───────────▶       세션 1 깨어남 → 실행 → 보고
 * 지금 뭐 해         ───────────▶       열린 세션 전부 답함
 ◀───────────────  🟢 my-app · 18:27  지금: 재시도 테스트 작성 …
```

양방향 모두 조용하게 만들어져 있다. 보내는 쪽은 손으로, 세 경우에만 — heartbeat 도, 보고하는
폴러도 없다. 받는 쪽은 훅 둘과 세션당 감시자 하나로, 아무도 쓰지 않는 동안엔 비용이 없다.
자리를 비운 사용자에게 에이전트가 닿는 유일한 통로는 가장 쉽게 소음이 되는 통로이기도 해서, 이
스킬의 절반은 **보내고 듣는 법**이고 나머지 절반은 **안 보내는 법**이다.

아래에서 `<s>` 는 `~/.claude/skills/telegram-notify/scripts` 를 뜻한다.

## 보고가 이런 모양인 이유

에이전트에게 긴 작업을 맡기고 자리를 뜨면 두 가지가 궁금해진다.

1. **끝났나? 막혔나?** — 터미널 없이는 알 수 없다
2. **아직 살아 있나?** — 이게 어려운 쪽이다

2번이 설계를 결정했다. 자유 서술 보고는 2번에 **답하지 못한다**: 한 시간째 아무것도 안 움직였어도
"작업 중입니다"라고 쓸 수 있고, 멀쩡한 세션의 같은 문장과 글자 하나 다르지 않다. 그래서
**보고의 절반은 에이전트가 쓰지 않는다:**

```
🟢 my-app · 18:27
지금: 결제 실패 재시도 테스트 작성
직전: 로그인 폼 검증 추가
다음: 결제 화면 리팩토링
⎇ feat/checkout · ● 결제 실패 재시도 (12분 전) · 미커밋 3   ← 기계가 읽는다
```

마지막 줄 — 시각, 브랜치, 마지막 커밋과 그 나이, 미커밋 파일 수 — 은 `git` 과 시계에서 나온다.
보고 두 개를 나란히 놓으면, 문장이 뭐라고 하든 **그 사이에 실제로 뭔가 움직였는지**가 보인다.
필드를 하나도 주지 않아도 이 줄은 나가므로, 인자 없이 부르는 것만으로 살아 있음이 증명된다.

막혔을 때는 **글리프 하나만 바뀐다** — 알림 미리보기만 보고 열어볼지 판단할 수 있어야 하기
때문이다:

```
🔴 my-app · 18:31
막힘: 배포 서명 키 비밀번호 필요 — 사용자만 알고 있음
⎇ feat/checkout · ● 결제 실패 재시도 (16분 전)
```

## 설치

폴더를 복사한다. 빌드도 패키지도 없다.

```bash
cp -r skills/telegram-notify ~/.claude/skills/
```

```powershell
Copy-Item -Recurse skills\telegram-notify "$env:USERPROFILE\.claude\skills\"
```

또는 에이전트에게 이 저장소 주소와 스킬 이름을 주면 같은 일을 한다. 다음 세션부터는 *"텔레그램
연동해 줘"* 한 마디면 에이전트가 체크리스트를 따라간다.

### 여기서 시작

```bash
node <s>/install.mjs
```

한 화면: 지금 뭐가 돼 있고 다음 단계가 뭔지. **USER** 로 표시된 단계는 에이전트가 못 한다 —
일부러 그렇다. 봇 생성은 사람만 할 수 있고, 상시 자동화 설치(와 그 권한 부여)는 채팅 메시지가
이 머신에서 아무거나 실행하지 못하게 막는 바로 그 지점이다. `install.mjs --perms` 가 붙여넣을
권한 블록을 출력한다 — 이 스킬의 스크립트와 이름이 정해진 작업 하나만 허용하는 좁은 규칙.

### 연동 (처음 한 번, 2분)

```bash
node <s>/tg-setup.mjs --check      # 이미 되어 있나?
```

`2` 가 나오면:

1. 텔레그램에서 **@BotFather** → `/newbot` → 토큰을 복사한다
2. **새 봇에게 아무 메시지나 하나 보낸다** — 이걸 빠뜨리면 다음 단계가 `no chat found` 로 끝난다.
   봇은 먼저 말을 걸 수 없어서, 사용자가 말을 걸어야 어디로 보낼지 알게 된다
3. `node <s>/tg-setup.mjs <TOKEN>`

chat id 를 찾고, 저장하고, **시험 발송까지 해서 경로 전체가 되는지 증명한다** — 저장만 되고 못
보내는 상태로 끝나지 않는다. 절차·종료 코드·API 오류표: [`references/setup.md`](references/setup.md).

사람이 할 일은 이게 전부다: 토큰, 그리고 봇에게 메시지 하나. 훅·모드·감시자 설정은 에이전트가
한다 (하네스가 묻는 곳에서는 사용자의 승인을 받아).

## 보내기

```bash
# 상태 보고 (권장)
node <s>/report.mjs --now "테스트 작성" --done "재시도 로직 구현"
node <s>/report.mjs --blocked "서명 키 비밀번호 필요"
node <s>/report.mjs --dry                      # 형식만 출력, 보내지 않음

# 임의 메시지
node <s>/tg.mjs "내용"
echo "내용" | node <s>/tg.mjs
```

성공하면 `200` 만 출력한다.

라벨은 기본이 한국어다. `TG_LANG=en` 이면 `now` / `done` / `next` / `blocked`.

## 모드 — 어디로 보고할까

**사용자가 지금 어디에 있느냐**의 문제지 작업의 문제가 아니다.

```bash
node <s>/mode.mjs        # 현재 모드
node <s>/mode.mjs 2      # 설정
```

| 모드 | 터미널 | 텔레그램 | 언제 |
|---|---|---|---|
| **1** | 전부 | **안 보냄** | 자리에 있음 — 화면에 이미 있는 걸 또 울릴 이유가 없다 |
| **2** | 전부 | 중요한 순간에만 | 기본값 — 있지만 잠깐 나갈 수 있음 |
| **3** | **짧게** | 전부 | 나가 있음 — 터미널은 줄여 토큰을 아끼고, 보고는 메시지로 |

모드 1에서는 `tg.mjs` 와 `report.mjs` 가 **보낼 내용을 출력만 하고 끝난다.** 잃는 것도 없고
울리지도 않는다.

## 읽기 — 봇은 뒤에서 듣고 있지 않다

**처음 쓰는 사람에게 가장 먼저 말해야 할 것.** 봇에게 보낸 메시지는 에이전트가 읽으러 갈 때까지
조용히 기다린다. 뒤에서 듣고 있으려면 루프가 필요하고, *보내는* 루프가 P0-1 이 금지하는 것이다.
(열린 세션 하나를 메시지로 깨우려면 [감시자](#감시자--메시지가-놀고-있는-세션을-깨운다).)

```bash
node <s>/tg-read.mjs               # 기다리는 것
node <s>/tg-read.mjs --consume     # …그리고 읽음 처리
```

`getUpdates` 는 스트림이 아니라 우편함이라 늦게 읽어도 잃는 게 없다. 이걸 말해 주지 않으면
"연동이 안 됐다"로 읽힌다 — 처음 쓰는 사람은 정확히 그렇게 읽는다.

## 훅 — 에이전트의 습관이 아니라 하네스가 하는 감지

**스킬은 문서다.** 에이전트가 이미 행동하고 있을 때 무엇을 할지를 바꿀 뿐, 턴 안에서 수신함을
읽거나 보고를 보내는 것은 스스로 일어나지 않는다. 에이전트의 기억에 기대는 것은 언젠가 안 일어난다.

**훅은 하네스가 실행한다.** `~/.claude/settings.json` 에 둘을 건다:

```json
{ "hooks": {
  "Stop":         [{ "hooks": [{ "type": "command", "command": "node ~/.claude/skills/telegram-notify/scripts/stop-hook.mjs",     "timeout": 30 }] }],
  "SessionStart": [{ "hooks": [{ "type": "command", "command": "node ~/.claude/skills/telegram-notify/scripts/session-start.mjs", "timeout": 20 }] }]
} }
```

- **Stop** — 턴이 끝날 때마다: 수신함을 읽고, **모드 3이면** 보고를 보내고, 온 것이 있으면
  `decision: block` 으로 메시지를 돌려줘서 **턴이 끝나지 않고 답하게** 한다. 무한루프는 불가능하다
  — block 전에 메시지를 소비하므로 다음 stop 에서는 수신함이 비어 있다. 모드 2는 일부러 자동
  보고를 하지 않는다 — 터미널이 이미 닿았고, 매 턴 끝의 메시지는 P0-1 이 막으려는 그 소음이다.
- **SessionStart** — 새 세션의 컨텍스트에 기다리는 메시지를 찍고, 감시자 설정이 켜져 있으면
  감시자를 켜라는 지시까지 찍는다 (아래).

두 훅 모두 어떤 실패에도 아무것도 출력하지 않고 0으로 끝난다. 고장 난 알림기가 세션을 붙잡아서는
안 된다.

## 세션이 여러 개, 봇은 하나 — 번호를 앞에 붙인다

채팅방도 봇도 하나인데 보통 프로젝트마다 에이전트가 하나씩 돌고, 전부 같은 수신함을 읽는다 —
그리고 `getUpdates` 는 **봇 전체**를 한 번에 확인 처리한다. 하나만 가져가고 하나는 남겨두는
방법이 없다. 아무 장치가 없으면 먼저 멈춘 세션이 전부 가져가고, 다른 프로젝트 앞으로 온 메시지가
엉뚱한 세션에게 소비된다.

`route.mjs` 가 가장 단순한 방법으로 해결한다. **프로젝트마다 번호를 주고, 사용자가 번호를 맨
앞에 붙인다.**

```
2 테스트 돌려          -> 2번 프로젝트에만
1,3 테스트 돌려        -> 1번과 3번, 각각 한 번씩
* 테스트 돌려          -> 그 순간 열려 있는 세션 전부
테스트 돌려            -> 먼저 멈추는 세션 하나 (세션이 하나만 열려 있을 때 맞는 동작)
?                     -> 봇이 목록을 알려준다
```

```bash
node <s>/route.mjs
```

```
Put the number first to pick a session:
1 my-app
2 other-app    (closed)
3 old-app      (never run)
```

번호는 프로젝트의 훅이 처음 돌 때 배정되고 재사용되지 않는다 — 한 번 외운 번호는 계속 같은
프로젝트를 가리킨다. 목록은 새 프로젝트가 번호를 가져갈 때만 자동으로 전송된다 — 사용자가 알던
목록이 낡아지는 유일한 순간이다.

**열려 있는지는 등록이 아니라 관측이다.** 모든 세션은 `~/.claude/projects/<인코딩된 cwd>/<세션
id>.jsonl` 에 기록을 남기고 작업하면서 그 파일을 건드리므로, 디렉터리의 최신 mtime 이 그
프로젝트가 마지막으로 움직인 시각이다. 아무것도 자기를 등록하지 않고, 죽은 세션은 치울 것을
남기지 않는다. 실측: 열린 세션은 0~1분, 닫힌 세션은 50분 이상 — 신호가 깨끗하게 갈린다. 닫힌 줄은
**지우지 않고 표시만** 한다 — 목록을 읽고 번호를 입력하는 사이에 줄이 사라지는 것이 번호로
막으려던 바로 그 실패다.

**번호 없는 메시지는 전체가 아니라 세션 하나 — 먼저 멈추는 쪽 — 에게 간다.** 세션이 하나면 맞고,
둘이면 동전 던지기다. 사용자에게 한 번은 말해 둔다.

그 아래에서 훅과 감시자는 텔레그램을 **스풀 파일**로 옮긴 뒤 자기 몫만 꺼내 간다 — 자기 번호,
`*`, 또는 번호 없음. 수신자가 여럿인 메시지는 마지막 수신자가 가져갈 때까지 남고, `*` 는
**스풀에 넣는 순간** 그때 열린 세션들로 확정된다 — "전부"는 보낸 시점에 있던 전부다. 열려 있지
않은 프로젝트의 메시지는 하루까지 기다리다 버려진다 — 2주 뒤에 난데없이 튀어나오지 않도록. 스풀
작업은 전부 `wx`(이미 있으면 실패하는 생성) 락 파일 아래의 읽고-판단하고-쓰기다 — 두 Stop 훅이
같은 초에 끝날 수 있고, 락 없이는 한 세션이 이미 가져간 메시지가 되살아나 두 번 배달된다. 1분
넘은 락은 죽은 프로세스의 것이라 인수하고, 락을 아예 못 잡으면 락 없이 실행한다 — 중복이 침묵보다
낫고, 침묵이야말로 이 스킬이 막으려는 실패다.

```bash
node --test skills/telegram-notify/test/route.test.mjs    # 테스트 24개
```

## 감시자 — 메시지가 놀고 있는 세션을 깨운다

Stop 훅은 **턴이 끝날 때** 수신함을 읽는다. 턴과 턴 사이 — 에이전트가 입력을 기다리며 놀고 있는
동안 — 에는 아무것도 돌지 않으므로, 그때 보낸 메시지는 누군가 터미널에서 엔터를 칠 때까지 그대로
앉아 있다. 폰에서 보면 대답 없는 봇이다.

`watch.mjs` 가 그 틈을 **세션 하나에 대해, 세션이 사는 동안** 메운다. 이 세션 앞으로 온 메시지를
한 줄에 하나씩 출력하는데, 하네스의 **Monitor** 도구 아래에서 돌리면 각 줄이 세션을 깨우는
이벤트가 되고, 세션은 그 줄이 터미널에 입력된 것처럼 답한다:

```
Monitor({ command: 'node ~/.claude/skills/telegram-notify/scripts/watch.mjs',
          description: 'Telegram messages for this session', persistent: true })
```

**켜는 것은 사용자가 아니라 세션의 일이다.** 머신 단위 설정 하나:

```bash
node <s>/watch.mjs --on       # 새 세션마다 시작 시 감시자를 켠다
node <s>/watch.mjs --off      # 다시 수동으로
node <s>/watch.mjs --status
```

켜져 있는 동안 SessionStart 훅이 위의 `Monitor(...)` 호출을 그대로 새 세션의 컨텍스트에 찍고,
**세션의 첫 행동이 그것을 실행하는 것**이다 — 사용자의 요청을 읽기 전에. 이것이 "창마다 들으라고
말해 주기"를 한 번 올리는 스위치로 바꾼다. 훅 없이 시작했거나 설정이 꺼져 있으면, 사용자가
"텔레그램으로 보내겠다"고 할 때 켠다. 설정과 훅이 맞는지는 `install.mjs` 가 보여 준다.

동작 원리: `getUpdates` 요청 하나를 최대 50초 열어 둔다 (텔레그램의 롱 폴). 도착한 것은 **훅과
같은 스풀**에 넣고 확인 처리한 뒤, 이 세션 몫만 꺼낸다. 스풀은 **매 회차** 확인한다 — 이
프로세스가 무언가 받아왔을 때만이 아니라. 이 세션 앞으로 온 메시지를 다른 세션의 훅이나 감시자가
먼저 받아갔을 수 있고, 텔레그램은 그것을 다시 보여주지 않는다. 출력된 것은 이미 스풀에서 빠졌으므로
다음 Stop 이 두 번 배달하지 않는다.

감시자는 스스로는 아무것도 보내지 않는다. 유일하게 답하는 것은 `?` 에 대한 세션 목록이고, 그것도
모드가 전송을 허용할 때다 — 배선에 대한 질문이라 세션을 깨울 가치가 없다. 나머지는 세션이
`tg.mjs` 로 직접 답한다.

**세션 둘, 감시자 둘.** 텔레그램은 봇당 열린 `getUpdates` 를 하나만 허용한다. 두 번째 감시자가
첫 번째를 끊는다 (`Conflict: terminated by other getUpdates request`). 진 쪽은 15초 동안 폴을
이긴 쪽에 맡기고 그동안 2초마다 스풀을 읽는다 — 이긴 쪽이 모두의 몫을 스풀에 넣으니까 — 그 뒤
다시 폴을 요청해서, 이긴 쪽이 사라졌으면 넘겨받는다. 잃는 것은 없고, 진 쪽은 최대 2초 늦고, 감시자
둘이 합쳐 분당 4회의 추가 요청을 낸다 (60초 실측). 감시자 없는 세션도 다음 Stop 에서 메시지를
받는다.

**P0-1 과의 관계.** 그 규칙이 막는 것은 *보내는* 루프다. 감시자는 반대 방향, 받기 위한 대기다.
놀 때의 비용은 열린 연결 하나이고, 조용한 하루는 이벤트 0개다. 그리고 세션에 묶여 있다 — 하네스의
태스크 목록에 보이고, 한 번의 호출로 멈추고, 세션이 끝나면 사라진다 — 그래서 주인보다 오래 살
수도, 여러 개로 불어날 수도 없다. 분리된 셸 루프가 실제로 겪는 두 가지 실패가 바로 그것이다.

```bash
node <s>/watch.mjs --once                                  # 첫 메시지 하나 받고 종료: 배선 확인용
node --test skills/telegram-notify/test/watch.test.mjs     # 테스트 6개
```

## 충돌할 수 있는 세션들

한 머신의 두 세션은 서로를 볼 수 없는데, 같은 저장소·같은 파일·같은 포트에 있을 수 있다. 세션
목록이 그들이 만나는 자리다:

```bash
node <s>/route.mjs --note "feature/x 를 main 에 리베이스 중"    # 이 세션이 하는 일
node <s>/route.mjs                                             # 다른 세션들은 뭘 한다고 하나
node <s>/route.mjs --tell 2 "package.json 10분만 손대지 마"     # 2번에게 메시지 (`1,3`, `*` 도)
```

메모는 세션 번호 옆의 한 줄로, 사용자에게는 `?` 에서, 다른 세션에게는 목록에서 보인다.
`--note ""` 로 지운다. `--tell` 로 남긴 메시지는 스풀을 거쳐 사용자의 메시지와 같은 길로 상대
세션에 닿는다 — 다음 Stop 에서, 감시자가 있으면 즉시 — `(session N)` 표시가 붙어 세션이 보낸
것으로 읽힌다. 방송은 보낸 세션에게 돌아오지 않는다. 새로 도는 것은 없다: 이미 있는 우편함이다.

에이전트의 규칙: **충돌할 수 있으면 하는 일을 적고, 충돌하기 전에 목록을 읽고, 필요하면 상대
세션에게 말한다.** 사용자도 메모를 본다 — 그것으로 번호를 고른다.

## 세션이 끝나면

이 스킬이 띄우는 모든 것은 세션에 속하고, 세션과 함께 사라진다:

- **감시자.** 하네스가 세션 종료 시 모니터 태스크를 죽인다 — 지금까지의 모든 세션 종료에서
  관측됨. 자신을 띄운 세션보다 오래 산 `watch.mjs` 는 없었다. 관측되지 않는 종료(하네스가 정리
  없이 죽는 경우)를 위해 감시자는 매 회차 자신을 띄운 프로세스가 살아 있는지 확인하고, 없으면
  스스로 멈춘다.
- **훅**은 끝까지 돌거나 타임아웃된다. 아무것도 열어 두지 않는다.
- **스풀**은 돌아오지 않는 세션의 메시지를 24시간 뒤 버린다. 죽은 프로세스가 남긴 락은 60초 뒤
  인수된다.
- **장부**는 번호를 유지하고(사용자의 목록이 그대로 유효하도록) transcript 나이로 닫힘을
  표시한다. 치울 것이 없다.

`ps` / `tasklist` 로 `watch.mjs` 를 찾는 것이 감사의 전부다. 세션이 끝났는데 남아 있다면 버그다.

## 비용 — 실측

노트북 한 대: Intel Core i5-1340P (12코어/16스레드), RAM 16 GB, Windows 11 Pro, Node 22, 봇
하나. 네트워크 수치는 그 머신에서 `api.telegram.org` 까지의 왕복이라 회선마다 다르고, 메모리·CPU
는 Node 프로세스의 것이라 어디서나 비슷할 것이다.

| 구성요소 | 언제 | 비용 |
|---|---|---|
| 감시자 (`watch.mjs`) | 세션당 프로세스 하나, 세션이 사는 동안 | RSS 50 MB, CPU 분당 47 ms (코어 하나의 0.08 %), 스레드 13, 유지되는 TCP 연결 1개; 유휴 시 50초마다 요청 하나 ≈ 0.8 KB/분 ≈ 1 MB/일; 조용한 날 이벤트 0개 |
| Stop 훅 | 턴이 끝날 때마다 | `node` 기동 (170–190 ms) + `getUpdates` 한 번 (350 ms–3.8 s, 순수 네트워크); 합쳐서 벽시계 1.2–3.1 s, 턴이 이미 끝난 뒤에 |
| SessionStart 훅 | 세션당 한 번 | 같은 모양: 1.2–2.5 s |
| 목록·설정 명령 | 요청 시 | 180–230 ms, 네트워크 없음 |
| 스풀·장부·락 | 훅이나 감시자의 매 회차 | `~/.claude/local` 의 작은 JSON 파일 셋; 락은 밀리초 단위로만 잡는다 |
| 세션 *N* 개 | | 감시자 *N* 개: *N* × 50 MB, *N* × 0.08 % CPU; 폴은 하나가 잡고 나머지는 양보 — 둘이면 분당 4회 추가 요청 |

세션 사이에는 아무것도 돌지 않는다. 텔레그램에 닿지 못한 훅과 감시자는 아무것도 출력하지 않고
나중에 다시 시도하며, 어느 것도 훅 타임아웃보다 오래 턴을 붙잡을 수 없다.

## 메시지로 세션 시작하기 — 열린 세션이 하나도 없을 때

*"세션 끝나도 되게 해 줘"* 는 머신마다 답이 다르다. 추측하지 말고 탐지한다:

```bash
node <s>/reachability.mjs
```

OS, `claude` CLI, 쓸 수 있는 스케줄러, 자격증명을 읽고 후보 넷을 **확실성과 오버헤드로 채점해서**
하나를 고른다. 설치는 하지 않는다 — 고르는 것은 사용자다. 기준과 근거:
[`references/reachability.md`](references/reachability.md).

훅과 감시자는 **이미 돌고 있는 세션 안에서만** 도움이 된다. 메시지가 세션을 *시작*하게 하려면
아무것도 안 돌 때 도는 것이 있어야 한다: OS 스케줄러가 부르는 `bridge.mjs`.

```bash
node <s>/bridge.mjs --install     # 설치 명령만 출력, 설치는 안 함
node <s>/bridge.mjs --dry         # 뭘 실행할지만 확인
```

한 번 폴링: 수신함을 읽고, 온 것이 있으면 `claude -p` 로 실행하고, 답을 돌려보낸다. **루프가
아니다** — 한 번 읽고 끝나므로 주기는 스케줄러가, 끄는 것은 OS 가 소유한다. 락 파일(같은
저장소에 두 번째 에이전트 금지), 락을 잡은 뒤에야 소비, 실행 타임아웃 — 각각 실제로 일어나는
실패 하나씩을 막는다.

윈도우에서는 [`scripts/install-bridge.ps1`](scripts/install-bridge.ps1) 이 작업 설치기다.
`-WorkDir` 로 어느 디렉터리에서 답할지 정한다.

```powershell
cd ~/projects/my-app; ./install-bridge.ps1              # 이 폴더 기준으로 답하게
Disable-ScheduledTask -TaskName 'claude-telegram'      # 끄기, 한 줄
```

### 함정 — 브리지와 Stop 훅은 수신함 하나를 다툰다

`getUpdates` 의 offset 은 **읽는 쪽마다가 아니라 봇 하나에 하나**다. 브리지와 Stop 훅은 둘 다
수신함을 읽은 뒤 `last + 1` 로 소비하므로 **먼저 폴링한 쪽이 메시지를 가져가고 나머지는 영영
못 본다** — 그리고 둘의 폴링 주기는 대등하지 않다:

| | 폴링 | 이김 |
|---|---|---|
| 스케줄된 브리지 | 몇 분마다, 조건 없이 | 거의 항상 |
| Stop 훅 | 턴이 끝날 때만 | 그 턴 안에 브리지 tick 이 없었을 때만 |

둘 다 켜 두면 작업 중에 보낸 메시지는 **스케줄러가 가리키는 디렉터리에서 headless 로 실행**되고,
정작 보고 있는 세션은 아무 일 없이 끝난다. 밖에서 보면 채널 고장과 구별이 안 돼서 버그로
신고된다.

**둘은 배타적이고, 어느 쪽이 맞는지는 사용자가 어디 있느냐로 갈린다:**

| 상황 | 켜 둘 것 |
|---|---|
| 자리에 있고 세션이 열려 있다 | **Stop 훅만** — 메시지가 그 세션에 `decision: block` 으로 꽂혀 턴이 이어진다 |
| 자리를 비웠고 열린 세션이 없다 | **브리지만** — 달리 답할 수 있는 게 없다 |

`install-bridge.ps1` 은 Stop 훅이 이미 걸려 있으면 설치를 **거부하고** 이 선택을 대신 출력한다.
정말 둘 다 두려면 `-Force`, 그리고 자리에 있는 동안은 `Disable-ScheduledTask`.

> **설치 전에 반드시 말할 것:** 봇에게 메시지를 보낼 수 있는 사람은 이 머신에서 에이전트를
> 실행시킬 수 있고, 막는 것은 봇 토큰뿐이다. 에이전트는 **대신 설치하지 않는다** — 명령을 건네서
> 끄는 스위치를 사용자가 갖게 한다.

## P0 — 이 스킬이 막으려는 것

| # | 규칙 |
|---|---|
| 0-1 | **자동·주기 전송을 만들지 않는다** — heartbeat, poller, cron, 스케줄러, 전송하는 훅, 반복 보고 태스크. 막는 것은 **보내는** 루프이고, 받기 위한 대기(`watch.mjs`)는 그것이 아니다 |
| 0-2 | **토큰을 저장소에 두지 않는다** — `~/.claude/local/telegram.env`, 모드 `0600`, 그 외 어디에도 |
| 0-3 | 토큰·chat id 를 원문으로 출력하지 않는다 — 마스킹된 출력만 |
| 0-4 | 보내기 전에 사용자 입장에서 읽는다 — 진행 중계 금지 |
| 0-5 | "그만"이면 **프로세스까지 죽인다** |

### 0-1 과 0-5 는 같은 사고에서 나왔다

heartbeat·poll 스크립트를 지워도 멈추지 않는다: 셸이 파일을 이미 메모리에 읽어 둔 채 프로세스
여러 개가 살아서 몇 시간 더 보냈다. **파일 삭제는 중지가 아니다.** `SKILL.md` 에 프로세스를 찾아
죽이는 명령이 OS 별로 있다.

> N분마다 오는 "지금 X 하는 중"은 정보가 아니라 소음이다. 메시지의 기준: **자리를 비운 사용자가
> 이걸 알았더라면 행동이 달라졌을까?**

## 이식

자격증명은 `~/.claude/local/telegram.env` 한 파일에 있고 프로젝트와 무관하다.

| 상황 | 할 일 |
|---|---|
| 새 프로젝트 | 없음 |
| 새 머신 | 그 파일을 만든다 (설정 재실행, 또는 복사) |
| 프로젝트마다 다른 봇 | 환경변수 `TG_TOKEN` / `TG_CHAT` 이 파일보다 우선 |
| CI · 컨테이너 | 같은 변수를 주입. 파일 불필요 |
| 파일 위치 변경 | `TG_ENV_FILE` |
| 영어 보고 라벨 | `TG_LANG=en` |
| 작업 디렉터리 변경 | `CLAUDE_TG_DIR` (장부·스풀·락) · `CLAUDE_PROJECTS_DIR` (transcript, 열림 판정용) |

**다른 메신저.** `scripts/tg.mjs` 의 `send()` 만 갈아끼운다 — Slack 이든 Discord webhook 이든
`{ ok, status, body }` 를 돌려주면 `report.mjs` 는 그대로 동작한다. 형식·보내는 경우·P0 는
채널과 무관하다. 읽기와 라우팅이 텔레그램 모양인 곳은 하나다: `tg-read.mjs` 의 `inbox()` 와
그 `getUpdates` offset.

**다른 하네스.** 스크립트는 평범한 Node 이고 누가 부르는지 모른다. 하네스가 제공해야 하는 것과
이 스킬이 그것을 쓰는 곳:

| 필요한 것 | 쓰는 곳 | Claude Code 에서는 |
|---|---|---|
| 턴이 끝날 때 명령을 실행하고, 턴을 이어갈 수 있게 | 수신함 읽기, 멈추기 전에 답하기 | `Stop` 훅과 `decision: block` |
| 세션 시작 시 컨텍스트에 텍스트 넣기 | 기다리는 것 보여주기, 감시자 켜기 | `SessionStart` 훅 |
| stdout 한 줄이 에이전트를 깨우는 백그라운드 프로세스 | 감시자 | `Monitor` 도구 |
| 프로젝트별 활동 신호 | 어느 세션이 열려 있나 | `~/.claude/projects` 의 transcript mtime |

셋째가 없어도 전부 동작한다 — 메시지가 즉시가 아니라 다음 턴 끝에 도착할 뿐이다. 넷째가 없으면
`CLAUDE_TG_LIVE_MIN` 을 크게 잡거나 등록된 세션을 전부 열린 것으로 친다.
