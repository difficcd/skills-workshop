# <프로젝트> UI 규칙

> 색·스케일·컴포넌트 레시피·네이티브 UI 금지·QA 명령은 **전역 skill `monotone-accent-ui`** 에 있다.
> 여기에는 **이 프로젝트에만 해당하는 것**만 적는다. 중복해서 적지 말 것 — 에이전트가 헷갈린다.

## 1. 재사용 자산 (새로 만들지 말 것)

새 UI를 만들기 전에 아래를 먼저 찾아본다. 없을 때만 새로 만든다.

| 필요한 것 | 쓸 것 |
|---|---|
| 체크박스 / 날짜 / 시간 선택 | `src/components/inputs.jsx` — `AccentCheckbox` `DatePicker` `TimePicker` (body 포털 팝오버 포함) |
| 마크다운 렌더/편집 | `src/components/Markdown.jsx` — `MarkdownDoc`(`.md-body`) `PlainDoc` |
| 로컬 저장 | `src/useLocalStorage.js` — 함수형 업데이트 + 같은 탭 동기화 이벤트 내장 |
| <추가> | <경로 · 언제 쓰는지> |

같은 성격의 수정은 **아래 전부**에 적용됐는지 확인한다. 하나만 고쳤다면 이유를 남긴다.

- [ ] <홈 / 대시보드>

## 3. 데이터 스토어

| 키 | 담는 것 | 주의 |
|---|---|---|
| `<app>-<name>` | <구조 한 줄> | <이 키를 쓰는 다른 화면 / 마이그레이션 주의점> |

**규칙**: 구조 변경 전 커밋 + 백업. 한 스토어를 두 화면이 쓰면 한쪽이 상시 미러링으로 다른 쪽을 덮어쓰지 않게 한다(전역 skill P0-2).

## 4. 크로스 기능 규칙

예) 전체검색 하이라이트는 화이트리스트 방식(`.md-body`, `[contenteditable]`, `[data-hl]`)이므로
**유저 데이터를 텍스트로 렌더하는 새 요소에는 `data-hl=""` 필수**, 시스템 문구는 `data-hl-skip`.
접히거나 닫히는 새 표면에는 `global-search-reveal` 리스너를 달아 스스로 열리게 한다.

→ 프로젝트의 크로스 기능(검색·알림·단축키·동기화)마다 "새 UI를 만들 때 추가로 해야 하는 일"을 한 줄씩.

## 5. 도메인 상태 전이

예) 항목 상태: **안읽음 → 다시보기(보관) / 읽음(퇴장)**.
"그냥 닫기"와 "처리했음"은 다른 행동이며, 읽음 처리된 항목도 전용 섹션에서 가역적으로 복구 가능해야 한다.

→ 이 프로젝트에만 있는 상태 기계를 적는다. 진입·이탈·표시 위치·필터링·복구 경로 5개를 모두 명시.
